## 1.1 ความเป็นมาและความสำคัญ

รายวิชา Pre-Project และ Project ถือเป็นรายวิชาสำคัญในระดับปริญญาตรี โดยเฉพาะในสาขาวิศวกรรมศาสตร์และเทคโนโลยี เนื่องจากเป็นรายวิชาที่เปิดโอกาสให้นักศึกษาได้บูรณาการความรู้ที่เรียนมาในวิชาต่าง ๆ และนำมาประยุกต์ใช้ในการวางแผน ออกแบบ และพัฒนาโครงงานจริง วิชา Pre-Project มุ่งเน้นให้ผู้เรียนค้นคว้าและวางแผนเบื้องต้น ทั้งการกำหนดปัญหา วัตถุประสงค์ ขอบเขต รวมถึงแนวทางการดำเนินงาน ขณะที่วิชา Project เป็นการลงมือปฏิบัติตามแผนที่วางไว้เพื่อให้ได้ผลงานที่สมบูรณ์ สามารถนำไปใช้งานได้จริง กระบวนการเรียนรู้ในรายวิชาเหล่านี้จึงมีความสำคัญต่อการพัฒนาทักษะด้านวิชาการและทักษะการทำงานจริงของนักศึกษา

อย่างไรก็ตาม การดำเนินโครงงานทั้งสองรายวิชามักประสบปัญหาหลายประการ ไม่ว่าจะเป็นการจัดเก็บข้อมูลที่ไม่เป็นระบบ การส่งงานและติดตามความคืบหน้าที่ทำผ่านหลายช่องทางจนเกิดความซ้ำซ้อนหรือการสูญหายของข้อมูล ตลอดจนการขาดระบบกลางที่เชื่อมโยงข้อมูลระหว่างวิชา Pre-Project และ Project อย่างต่อเนื่อง ทำให้การติดตามผลและการให้ข้อเสนอแนะจากอาจารย์ที่ปรึกษาไม่เป็นไปอย่างมีประสิทธิภาพ นอกจากนี้ยังไม่มีฐานข้อมูลโครงงานรุ่นก่อนที่สามารถใช้ค้นหาและอ้างอิงได้ ส่งผลให้เกิดปัญหาการทำหัวข้อซ้ำและทำให้นักศึกษารุ่นใหม่ไม่สามารถใช้ผลงานรุ่นพี่มาเป็นแนวทางในการต่อยอดองค์ความรู้ได้อย่างเต็มที่

ดังนั้นจึงมีความจำเป็นในการพัฒนา **"ระบบจัดการข้อมูลผลงานนักศึกษาในรายวิชาการเตรียมโครงงานและโครงงาน"** ขึ้นมาในรูปแบบเว็บไซต์ (Web Application) เพื่อเป็นระบบกลางในการจัดเก็บและบริหารข้อมูลโครงงานนักศึกษาอย่างเป็นระบบ ระบบนี้จะช่วยให้การติดตามและประเมินผลเป็นไปอย่างต่อเนื่องและโปร่งใส อาจารย์สามารถตรวจสอบและให้คำแนะนำได้สะดวก นักศึกษาสามารถส่งรายงานความคืบหน้าได้อย่างมีแบบแผน อีกทั้งยังจัดเก็บผลงานเข้าสู่คลังข้อมูลที่ค้นหาได้ง่ายและใช้ประโยชน์ต่อยอดได้จริง การมีระบบดังกล่าวไม่เพียงแต่ช่วยเพิ่มประสิทธิภาพในการเรียนการสอน แต่ยังช่วยยกระดับคุณภาพการบริหารจัดการข้อมูลโครงงานของภาควิชา ตลอดจนสนับสนุนการพัฒนาการเรียนการสอนในระยะยาวได้อย่างยั่งยืน

## 1.3 ขอบเขต

ระบบจัดการข้อมูลผลงานนักศึกษาในรายวิชาการเตรียมโครงงานและโครงงาน จะถูกพัฒนาในรูปแบบเว็บไซต์ (Web Application) โดยมีการแบ่งบทบาทผู้ใช้งาน และฟังก์ชันของระบบอย่างชัดเจน ดังนี้

### 1.3.1 ผู้ใช้งานระบบมี 3 ระดับ

#### 1) ผู้ดูแลระบบ (Admin)

| สถานะ | ฟังก์ชัน | หมายเหตุ |
|:---:|---|---|
| ✅ | จัดการบัญชีผู้ใช้งาน (นักศึกษาและอาจารย์): เพิ่ม/ลบ | `UsersController` CRUD |
| ❌ | จัดการบัญชีผู้ใช้: **รีเซ็ตรหัสผ่าน** | ❌ ยังไม่มี reset password API |
| ✅ | ตรวจสอบโครงงานทุกกลุ่มและดูรายละเอียดได้ทั้งหมดในระบบ | `AdminProjectsController` |
| ✅ | สร้าง/จัดการปีการศึกษา และจัดระเบียบข้อมูลตามรุ่น | `TermsController` + `SectionsController` |
| ✅ | จัดการระบบคลังข้อมูลโครงงาน เช่น แก้ไข/ลบ/อนุมัติโครงงาน | Archive toggle + Admin projects |
| ✅ | จัดการสมาชิกกลุ่มนักศึกษาและโครงงาน เพิ่ม/ลบ/แก้ไข | `AdminTeamsController` |
| ⚠️ | ส่งออกข้อมูล/รายงานผลการใช้งาน เช่น สถิติการส่งงาน, รายชื่อกลุ่ม | Utility มี แต่**ยังไม่มีปุ่ม Export ในหน้า Admin** |
| ✅ | มอบหมายงานได้ทุกกลุ่มและจัดการงาน เพิ่ม/ลบ/แก้ไข ได้ทุกโครงงาน | `TasksController` (role check ใน service) |
| ✅ | ให้ความคิดเห็นและข้อเสนอแนะผ่านระบบ | Comment module |
| ✅ | ให้เกรดนักศึกษาในช่วงท้ายภาคการศึกษา | `GradesController` (Admin only) |

#### 2) อาจารย์ที่ปรึกษา (Advisor)

| สถานะ | ฟังก์ชัน | หมายเหตุ |
|:---:|---|---|
| ✅ | เข้าสู่ระบบด้วยสิทธิ์อาจารย์ | JWT + Role check |
| ✅ | เข้าดูเฉพาะโครงงานที่ตนเป็นอาจารย์ที่ปรึกษา | `AdvisorsController.getMyProjects` |
| ✅ | ตรวจสอบความคืบหน้าของกลุ่มนักศึกษา | Advisor dashboard |
| ✅ | ให้ความคิดเห็นและข้อเสนอแนะผ่านระบบ | Comment module |
| ✅ | ค้นหาและดูประวัติโครงงานรุ่นก่อนเพื่อประกอบการให้คำแนะนำ | Archive search |
| ✅ | มอบหมายงานให้นักศึกษาประจำโปรเจกต์ที่เป็นที่ปรึกษา | Tasks (advisor access via service layer) |
| ✅ | จัดการงานที่มอบหมาย | Tasks CRUD |
| ✅ | ตรวจสอบและยืนยันคำขอเป็นที่ปรึกษาโครงงานของนักศึกษา | `ProjectsController.updateStatus` (approve/reject) |

#### 3) ผู้ใช้งานทั่วไป — นักศึกษา (Student)

| สถานะ | ฟังก์ชัน | หมายเหตุ |
|:---:|---|---|
| ✅ | ลงทะเบียนและเข้าสู่ระบบเพื่อใช้งาน | `POST /auth/signup` + `/auth/login` |
| ✅ | สร้างกลุ่มโครงงานในรายวิชา Pre-Project | `POST /teams` (Student only) |
| ✅ | ตอบรับคำเชิญหรือเชิญสมาชิกเข้าร่วมกลุ่มโครงงาน | `/teams/invite`, `/teams/join`, `/teams/reject` |
| ✅ | ระบุชื่อหัวข้อโครงงาน รายละเอียด และอาจารย์ที่ปรึกษา | `POST /projects`, `POST /projects/:id/advisor` |
| ✅ | อัปเดตรายงานความคืบหน้า พร้อมแนบไฟล์ หรือเขียนบันทึก | Tasks + Submissions + Attachments |
| ✅ | ตรวจสอบความคิดเห็นหรือคำแนะนำจากอาจารย์ที่ปรึกษา | Comment module |
| ✅ | ดำเนินงานต่อเนื่องจากรายวิชา Pre-Project ไปยัง Project ได้ | `POST /sections/:id/continue-to-project` |
| ✅ | ตรวจสอบคะแนน/ผลประเมินที่ได้รับจากอาจารย์ | `GET /grades` (student view) |
| ✅ | ค้นหาโปรเจคตามปี ชื่อหัวข้อ หรืออาจารย์ได้ | Archive search with filters |

### 1.3.2 ขอบเขตการทำงานของเว็บไซต์

#### 1) ระบบสมาชิกและการยืนยันตัวตน

| สถานะ | ฟังก์ชัน | หมายเหตุ |
|:---:|---|---|
| ✅ | ลงทะเบียนผู้ใช้งาน | `POST /auth/signup` |
| ✅ | เข้าสู่ระบบด้วยบัญชีและรหัสผ่าน | `POST /auth/login` (JWT) |
| ❌ | **รีเซ็ตรหัสผ่านผ่านอีเมลที่ลงทะเบียนไว้** | **ยังไม่มี** — ต้องสร้าง API + email service → **Phase 6b** |

#### 2) ระบบโครงงาน

| สถานะ | ฟังก์ชัน | หมายเหตุ |
|:---:|---|---|
| ✅ | บันทึกและอัปเดตรายงานความคืบหน้า | Tasks + Submissions |
| ✅ | แนบไฟล์ประกอบ เช่น รายงาน Word, PDF หรือรูปภาพ | Attachments model + Submission `file` field |
| ✅ | เปลี่ยนสถานะโครงงาน (ต้องทำ / กำลังทำ / ตรวจสอบ / เสร็จสิ้น) | Task `status` field |

#### 3) ระบบคลังข้อมูลโครงงาน

| สถานะ | ฟังก์ชัน | หมายเหตุ |
|:---:|---|---|
| ✅ | ค้นหาด้วยชื่อโครงงาน คำสำคัญ ปีการศึกษา หรือชื่ออาจารย์ | `GET /projects/archive` + filters (q, year, category, advisor) |
| ✅ | การค้นหาแบบขั้นสูง (ใช้หลายเงื่อนไขเชื่อมกัน) | Archive filters รองรับ multi-condition |
| ✅ | เข้าดูรายละเอียดโครงงาน (ชื่อผู้จัดทำ อาจารย์ที่ปรึกษา บทคัดย่อ ฯลฯ) | Archive detail view |

#### 4) ระบบรายงานและสถิติ

| สถานะ | ฟังก์ชัน | หมายเหตุ |
|:---:|---|---|
| ✅ | สรุปสถานะการส่งรายงาน | Admin Dashboard (Stats) |
| ✅ | สถิติการทำโครงงานของแต่ละรุ่น | Admin Dashboard (PieChart + BarChart) |
| ✅ | รายชื่อกลุ่มโครงงานทั้งหมด | Admin teams/sections pages |
| ⚠️ | **ส่งออกข้อมูล Excel/PDF** | Utility functions มีแล้ว แต่**ยังไม่มีปุ่ม Export ในหน้า** → **Phase 6c** |

#### 5) ระบบแจ้งเตือน (Notification System)

> ⚠️ **สถานะรวม: ทำบางส่วน — Frontend UI มี, Backend API ยังไม่มี → Phase 6a**

ระบบรองรับการแจ้งเตือนเหตุการณ์สำคัญที่เกิดขึ้นในระบบ โดยเฉพาะรายการที่เกี่ยวข้องกับสิทธิ์และบทบาทของผู้ใช้งานแต่ละประเภท

**ประเภทของเหตุการณ์ที่แจ้งเตือน:**

| สถานะ | เหตุการณ์ | หมายเหตุ |
|:---:|---|---|
| ⚠️ | การส่งรายงานความคืบหน้า / ไฟล์แนบใหม่ของกลุ่มโครงงาน | DB model มี, API ❌, trigger ❌ |
| ⚠️ | การแจ้งเตือนจากคอมเมนต์ | DB model มี, API ❌, trigger ❌ |
| ⚠️ | การอัปเดตสถานะงานที่ได้รับมอบหมาย (ต้องทำ/กำลังทำ/รอตรวจ/เสร็จ) | DB model มี, API ❌, trigger ❌ |
| ⚠️ | การให้คะแนนหรือการประเมินผลโครงงาน | DB model มี, API ❌, trigger ❌ |
| ⚠️ | การตอบรับหรือปฏิเสธคำขอเป็นอาจารย์ที่ปรึกษา | DB model มี, API ❌, trigger ❌ |
| ✅ | การเปลี่ยนแปลงสมาชิกกลุ่มโครงงาน (เชิญ) | ✅ Team invite ใช้ Notification table + frontend dropdown |
| ⚠️ | การสร้างปีการศึกษาใหม่หรือการมอบหมายงานจาก Admin | DB model มี, API ❌, trigger ❌ |

**รูปแบบการแจ้งเตือน:**

| สถานะ | รูปแบบ | หมายเหตุ |
|:---:|---|---|
| ✅ | In-app notification: ปุ่มกระดิ่ง / ศูนย์แจ้งเตือน | `NotificationDropdown` component |
| ⚠️ | บันทึก อ่านแล้ว/ยังไม่อ่าน | Frontend มี, **Backend API ❌** (hook ดึงจาก `/teams/pending-invites` เท่านั้น) |
| ⚠️ | ดูประวัติการแจ้งเตือนย้อนหลัง | **Backend API ❌** — ไม่มี `GET /notifications` |
| ✅ | ไม่แจ้งเตือนเหตุการณ์ที่ไม่เกี่ยวข้องกับผู้ใช้ | Notification model มี `user_id` filter |
